# Z Flip5 外屏带框投屏（macOS）

在 scrcpy 4.1 的实时渲染层叠加一个透明机型框，保留原来的实时视频、键盘和鼠标通道。安装后的外屏 `.command` 调用同目录 `Z Flip5 外屏.app/Contents/Resources/launch-cover.command`；内屏入口仍使用原版 scrcpy。

## 使用

1. 连接 USB，允许这台电脑进行 USB 调试，合上手机并正常解锁。
2. 双击「打开 Z Flip5 外屏.command」。入口按外屏编号和物理显示身份检查设备，不回退到内屏。
3. 激活投屏窗口后，点击 Mac 顶部菜单栏的「投屏方向」，选择 **0°（复位）/ 90° / 180° / 270°**，也可选向左或向右旋转90°。**Option+左/右方向键**沿用相同旋转逻辑。画面、机型框、开孔和鼠标坐标一起转，镜像被禁用；不会改变手机方向。窗口标题显示当前投屏角度，每次启动从0°开始。画面倒置时选180°，此时镜头随整机转到上方。
4. **F7每按一次顺时针旋转90°**，按住不连续旋转；F8 显示/隐藏机型框，F9 显示/隐藏缺口安全矩形。Mac 将功能键用作媒体键时加 Fn。
5. 关闭窗口结束投屏。若想录下机型框，录制电脑上的窗口；scrcpy 自带录像是手机原始视频，不包含电脑侧外框。

框内坐标统一经过等比缩放及旋转映射。可以在投屏窗口的机身区域按住鼠标左键，再滑入屏幕：触摸从穿过屏幕开孔的边缘开始，支持从下沿上滑。只在边框或镜头上点击、未按键移动不会触发手机。已经进入屏幕的左键拖动越过开孔后继续保持按下，触点限制在屏幕边缘，拖回可继续同一次手势；在机身区域松开也会正常结束。旋转、切换显示模式、缩放或失焦仍取消当前手势，取消后须重新按下。F9 只显示设备上报的 DisplayCutout 安全边距，不包括各个应用的系统栏、键盘或系统强制手势范围。

外框以用户参考照片修正外形，屏幕像素、圆角与安全线来自真机。详见 [参数来源与精度边界](../../dist/device-frames/CALIBRATION.md)。实时窗口、原型和效果图共用标准外框，只绘制一次。

## 维护与构建

- `cover_frame.c/.h`：贴图生命周期、等比几何、alpha 命中和鼠标取消。
- `cover_menu.m/.h`：macOS原生旋转菜单、当前角度和标题；通过独立SDL事件进入既有旋转入口，断连禁用，卸载移除菜单。
- `scrcpy.patch`：对官方 4.1 客户端的最小集成、服务端 CANCEL 清理整组指针，以及三星外屏输入映射回所选物理 Display 1 的兼容处理。
- `launch-cover.command`：识别外屏、读取安全边距、恢复真实开合状态和启动。
- `build-macos.sh`：下载并校验官方源码，在项目 Cache 内构建客户端与服务端，输出本机 `.app` 到 dist；不安装 APK。
- `dist/device-frames/zflip5-cover-overlay.svg`：唯一矢量维护源；由 `tools/device-frames/build.mjs` 同步 PNG 和原型。打包时使用标准 PNG，包内资源名保留 `zflip5-cover-calibrated.png` 以兼容入口。贴图矩形常量须与 `cover_frame.c` 一致。

需要 macOS、C 编译器、Homebrew 的 meson/pkgconf/sdl3/ffmpeg、JDK17 和 Android SDK Platform36 / Build Tools35。先配置 `JAVA_HOME`、`ANDROID_HOME`，在项目根目录运行：

```sh
tools/scrcpy-frame/build-macos.sh
```

构建结果依赖本机 Homebrew 动态库，供这台 Mac 使用；没有打包为可分发的通用 macOS 安装包。缓存中下载的上游源码可以重新生成，版本化的补丁与本目录源码才是维护入口。

构建官方版本固定为 4.1，源码包 SHA-256 为 `537b2ade623cb94b6edddfa5c61bf0b0af21484aa8365ea2531b686ea573249a`。

macOS 客户端与 Android 服务端构建成功，启动脚本语法检查和安装包严格签名校验通过。已从实际外屏入口启动，并在连接的 SM-F731U1 上确认 748×720 视频、照片修正后的单层外框、F9 缺口辅助线和两个方向的外框旋转。内屏入口校验值未变。

用户确认正向点击和滑动正常。自动输入检查捕获到正确的 DOWN/UP 坐标，修正输入目标后观察到正向应用中心打开。旋转后点击的完整复测受同时进行的用户操作影响，仍待单独确认；不能把画面旋转正确等同于所有方向的交互已通过。息屏和三星防误触保护也可能阻止页面响应，检查时需区分这些状态。本次没有修改或构建 Android 应用本体。

同日修正“屏幕外按住左键滑入”的拦截问题。针对实际 C 事件过滤器与透明 PNG 的本地检查覆盖三个下沿位置、四个旋转方向共12条穿入路径，以及边框点击、悬停、右键、松手、取消、失焦和取消后重入；全部通过。已重新构建、通过签名校验并更新实际外屏入口。自动拖动未能获得明确的手机界面响应，物理真机的边缘手势效果仍待用户手动确认。

## 手动旋转菜单 · 1.1

已构建并安装到用户指定的应用程序目录，严格签名校验通过；外屏客户端新增原生「投屏方向」菜单，内屏入口校验值保持不变。实际菜单选择270°后窗口标题随即更新，Option+左方向键恢复180°，画面、双摄和铰链一起旋转；已观察到180°时手机内容正向显示。

本地检查直接采用当前scrcpy坐标转换函数，覆盖5个屏幕位置×4个方向，误差不超过整数坐标换算的2像素；原有12条边缘穿入和取消生命周期检查也通过。只读独立复核确认事件编号无冲突、菜单释放与状态同步正确。记录在 `Cache/tests/scrcpy-frame-rotation/`。这些本地检查不能替代手机在各个方向下的完整触控验收。

用户随后在180°投屏窗口中手动确认：点击和滑动均正常。该确认覆盖180°当前真机状态，其余方向的完整触控验收仍与本地坐标检查区分。

## F7顺时针快捷键 · 1.2

F7的首次按下顺时针旋转90°，重复按下事件与松开事件只在电脑端消费，不转发手机。已构建并安装，严格签名校验通过；实际连续按四次F7，窗口依次显示0°→90°→180°→270°→0°。此次只验证新增快捷键和方向状态，未重复全部物理触控验收。构建记录位于 `Cache/tests/scrcpy-frame-f7/`。

## 拖出屏幕后保持触摸 · 1.3（2026-10-01）

已开始的左键拖动越过屏幕开孔不再发送取消；移动限制到开孔内边缘，鼠标拖回时沿用原触摸，真实松开才发送一次UP。在机型框上开始的单击仍被拦截，从机型框滑入仍从开孔边缘开始。失焦、旋转、几何变化和检测到丢失松开事件时保留取消清理，避免手机残留按下状态。

客户端及服务端构建、安装包严格签名校验成功，已更新现有外屏入口。使用实际透明贴图、当前事件过滤器和上游逆坐标函数，本地检查通过112条拖出/松开路径（四方向、四种缩放、七处边界）、28条直接在屏外松开、12条从机型框滑入，以及拖回、失焦、缩放与丢失松开事件。坐标额外考虑整数取整，并对真实注入像素重新检查透明开孔，避免旋转后坐标等于屏幕宽高或落入摄像头缺口。证据在 `Cache/tests/scrcpy-frame-drag-out/`；本地事件序列验证与用户物理手机手感验收分别记录。
