# 外屏快捷栏 · Flip Cover Controls

为三星 Galaxy Z Flip5 打造的外屏增强工具。项目起源于内屏损坏后的使用需求，希望只靠外屏，也能更方便地打开应用、切换任务、查看通知和控制常用功能，减少对展开手机的依赖。

当前应用版本为 **0.17.3**，面向 **Android 16 / One UI 8.5** 进行个人验证。无需 Root，部分系统操作需要 Shizuku 授权。

**[在线体验原型与互动教程](https://xiaomaoju.github.io/zflip5screenhelper/flipcover-tutorial.html)** · [全部原型页面](https://xiaomaoju.github.io/zflip5screenhelper/)

## 软件功能

### 外屏快捷栏与手势

自定义快捷按钮、顺序、位置及显示方式。在外屏底部双白条上滑，左侧打开通知中心，右侧打开控制中心；白条可见时长按可切换快捷栏显隐。支持摄像头缺口避让、四个旋转方向和导航手势安全区域。

Home 按钮可选择返回三星时钟首页，或通过已授权的 Shizuku 返回原生应用中心所在的卡片页；实际卡片位置由三星宿主决定。

### 控制中心与连接管理

集中调整亮度、音量、媒体播放及常用系统开关。控制中心支持固定 **3 / 4 / 5 列**，在原面板内添加、移除和拖动排序，最多保存30个快捷项。编辑区随可用宽度紧凑排布，支持跨区拖动、落点预览与撤销，点击“完成”后保存。

NFC 与移动热点可通过“＋”添加，点击切换、长按管理。热点详情支持名称、密码、频段、无人连接时自动关闭、二维码和当前连接设备。直接操作需要已授权且已连接的 Shizuku；接口不可用时提供系统入口。Android 快捷设置磁贴也可作为候选项，其执行能力属于实验性质。

### 应用桌面、文件夹与 Dock

应用中心采用固定 **5列×3行、每页15格** 的分页桌面，支持名称、别名和拼音搜索、手动排序、拖动整理、布局锁定及应用显示偏好。拖动应用可合并为文件夹，每个文件夹最多9项，占用2×2格，支持成员排序与拖出。

侧栏常用应用与 Dock 固定应用分别配置。Dock 最多固定4个应用，并按空间显示最多4个最近应用，提供应用中心和任务清理入口。应用启动成功或最近任务恢复成功后自动收起相关临时界面；失败时保留界面与提示。

### 外屏多任务

任务页支持横向连续拖动、惯性滚动和首尾回弹，点击卡片恢复应用，上滑关闭任务，下滑锁定或解锁。底部中央的清理按钮批量关闭可清理任务；批量清理保护固定应用、锁定任务和正在使用的任务，单项上滑可关闭固定应用的后台任务并保留固定入口。

预览使用系统可用的任务快照，同一次打开期间复用缓存；不可用时显示应用图标。任务锁只在本工具进程内有效，不保证应用在系统中常驻。最近任务仅处理所选外屏及所属用户的数据，不持久化历史。

### 通知、媒体与玻璃效果

通知中心显示已授权的活动通知，内容更新保持既有行和滚动位置。应用角标统计当前用户符合条件的活动通知，不等同于系统未读数。媒体卡片提供播放操作与详情进度，相关订阅随界面关闭而释放。

通知中心、控制中心、编辑区、详情窗口和多任务预览提供玻璃材质、折射及过渡动效。一次打开仅取样一帧所选外屏背景，关闭后释放；关闭背景效果、省电或系统拒绝取样时使用基础材质。

### 三星原生卡片

- **应用启动器卡片**：在三星卡片内浏览应用、打开文件夹、使用侧栏和完整 Dock，与浮窗共享布局、排序和偏好，保持5列×3行应用网格及固定字号。应用页用按钮翻页，侧栏竖向滚动，左右滑动留给三星宿主；布局编辑在浮窗启动器内完成。
- **小组件组合卡片**：提供6个独立入口，每张卡片可在4×4网格内组合多个已授权的 Android 桌面小组件，支持按应用选择预览、调整格位和尺寸，完成后保存布局。

### 设置与备份

One UI 风格设置页集中管理快捷栏、状态栏、控制中心、应用启动方向和布局偏好。状态栏缩放支持50%–150%；应用方向规则仅在从本工具显式启动应用时执行。支持配置导入导出与布局备份，包含别名、文件夹、布局锁定和显示偏好；恢复时保留本机显示器选择、权限和系统显示设置。

## 开始使用

1. 构建并安装调试 APK，打开应用设置。
2. 选择要使用的外屏，并按权限页面提示启用无障碍服务等所需权限。
3. 如需特权系统操作，启动 Shizuku 并授权本应用；查看通知和使用小组件时，分别完成对应的系统授权。
4. 根据外屏实际显示效果调整快捷栏、安全区域和应用布局；需要原生卡片时，在三星外屏的卡片管理中添加对应入口。

显示器专属操作只作用于选定外屏，不静默回退主屏；影响内外屏的系统开关会单独说明。项目不自动授权、不绕过锁屏，也不增加联网或分析追踪功能。三星固件、第三方小组件和系统窗口路由的兼容性仍需以物理真机验证为准。

## 从源码构建

准备 JDK 17、Android SDK Platform 37.0、Build Tools 36.0.0 和 Platform Tools，通过 `ANDROID_HOME` 或 Android Studio 配置 SDK 路径。项目使用 Gradle Wrapper 9.3.1、Android Gradle Plugin 9.1.1 和 Kotlin 2.4.10。

在项目根目录执行：

```sh
# macOS / Linux
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug

# Windows
gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

调试安装包输出到 `Cache/build-output.nosync/app/outputs/apk/debug/app-debug.apk`，测试和 Lint 报告位于 `Cache/build-output.nosync/app/reports/`。调试签名用于个人验证，发布版签名尚未配置。成功构建和本地检查不等同于三星外屏真机验收；设备端检查及物理真机流程见[验证说明](docs/project-history.md)。
