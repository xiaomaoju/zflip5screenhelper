# 应用启动器的两个宿主

浮窗和三星原生卡片分别拥有窗口与生命周期，共享内容、配置、动作规则与设计参数。更新公共功能时先修改共享层，再检查两个展示适配器；原生卡片不得另存一份启动器配置。

普通应用入口共用 `AppLauncher.applicationIntent`，使用 Android 标准的 MAIN/LAUNCHER 与 NEW_TASK、RESET_TASK_IF_NEEDED；不设置 MULTIPLE_TASK、CLEAR_TASK 或 CLEAR_TOP。已有任务按应用自身声明恢复原页面，没有任务才创建。浮窗、原生卡片及设置页在服务未运行时的应用入口保持相同语义，仍显式指定所选外屏，系统拒绝时不回退主屏。最近任务入口继续按具体任务身份恢复。

原生卡片的 Activity 点击入口不主动请求系统解锁，也不设置锁屏上显示。普通应用点击在创建入口时直接交给 `CoverService.launchApp`，由服务为两宿主解析当前所选外屏，共用 Context、方向规则和结果收尾；卡片不先解析或传入启动目标。服务未运行时通过应用 Context 识别目标，再调用共享 `AppLauncher`。不等待中转 Activity 焦点、不用它所在的屏幕或 PendingIntent 中旧的显示器编号否决启动。普通显式应用启动只检查应用组件、有效所选副屏和本次请求仍存活；屏幕电源、Keyguard和设备认证状态仅作诊断，不额外阻止标准 Android 启动。锁屏由系统执行，不使用解锁、锁屏上显示、强制亮屏或绕过系统安全的标记。暂停、息屏、停止或销毁取消尚未提交的普通应用请求；方向回调仍须核对同一个所选屏和入口存活。最近任务及侧栏系统动作保持原有亮屏/锁屏限制。技术原因只进入诊断，用户提示不要求处理 Activity 或显示器编号。

自动识别外屏时，`Displays.selected` 的面积与长宽比使用 `Display.Mode` 的物理宽高，不能使用可能被三星兼容缩放放大的 Activity `getRealSize()`。运行时布局仍使用既有显示几何，不把物理模式尺寸替换进UI测量；手动选择优先、主屏及私有显示器排除规则保持不变。诊断同时列出 Context 中的尺寸与物理模式尺寸，既有服务 dump 也包含有界启动记录。

`AppLauncher` 持有唯一 `AppLaunchDiagnostics` 内存环形记录，两个入口共用请求编号，记录阶段、启动路径、所选/请求/Activity显示器、屏幕与锁屏状态、生命周期、校验原因及系统异常类型。记录设备认证锁定状态，用于区分系统锁屏界面与用户认证；不把该字段当作放行条件。最多96条、每条256字符，仅事件发生时追加，不后台轮询、不写磁盘、不记录目标应用名称、组件、最近任务数据、通知内容或页面信息，不联网。设置中“问题诊断 → 复制检测结果”附上复制时最新的记录；进程结束后记录消失，复现后应在同次运行中及时复制。

文件夹仍占原2×2格位，方形表面按较短边居中，并在四边至少留2dp；相邻文件夹保留至少4dp缝隙。尺寸与预览由 `AppLauncherStyle.folderSide`／`folderGeometry` 统一计算，浮窗测量和原生RemoteViews共用；格位、拖动落点与点击区域不随表面内缩改变。原生卡片的编辑按钮继续显示短Toast“如需编辑，请到浮窗启动器内操作。”；刷新按钮等待真实最近任务结果后显示“最近应用已刷新”或返回的错误，息屏、切屏及已取消的请求不显示迟到提示。

旋转后的启动器边界同时核验所选显示器的方向和尺寸。服务尚未重算时，原生卡片使用当前显示器的缺口边界，不复用前一方向的内容窗口。导航栏隐藏后的旧边衬不作为启动器底部留白，真实强制 Home 边衬仍保留；系统边衬变化纳入窗口更新判断。

系统导航栏占用启动器底部时，`DockGeometry.hubContent` 先将侧栏、应用区和 Dock 作为整体向上移动实际重叠的距离，保留内部高度、固定5列3行、图标及间距；导航栏隐藏后恢复原位置。已有底部缺口或快捷栏已避让的距离不重复累加。上移不能越过顶部物理缺口或快捷栏可见边界，只有空间不足时才减少剩余高度；两宿主复用这一个边界结果。

快捷栏的 Home 可在「快捷栏与手势 → 按钮与布局 → Home 按钮效果」选择，唯一偏好为 `Prefs.homeAction`（`home_action`）。默认 `cards`“返回应用中心”：`CoverService.returnHome` 请求已授权的 Shizuku，通过 `ShellService` 的固定 `native_home` 操作恢复所选外屏上的三星卡片宿主，保留其当前卡片页。普通应用直接启动该宿主会被三星拦截并提示展开手机，因此此模式需要 Shizuku，不回退到普通应用启动。从原生应用中心打开应用后可返回原页，但不保证从其他卡片或宿主重建后定位到应用中心；不打开独立卡片展开页、不自动滑动、不回退主屏或全局 Home。

`clock`“返回锁屏页面”沿用原有全局 Home，回到三星时钟首页，不执行锁定设备动作，也不需要 Shizuku。两种模式执行前均检查所选外屏亮起且未锁定；延时或排队请求和回调再次检查窗口身份、目标屏及模式，防止切换模式后旧请求生效。`native_home` 服务执行前后还会核验屏幕与锁屏状态。选项立即保存，不在设置中执行 Home；配置和布局备份均包含此项，旧备份缺少该项时默认 `cards`。

|---|---|---|---|
| 应用、文件夹、固定项、侧栏、别名与显示偏好 | `Prefs`、`AppWorkspaceLayout` | `AppHubView`、`AppWorkspaceView` | `LauncherWidgetViews` |
| 筛选、排序、别名、角标和布局目录校验 | `AppLauncherModel`、`AppSearchIndex` | `AppHubView` | `LauncherWidgetViews` |

| Dock 容量、最近应用分组、清理范围 | `AppDockLayout`、`RecentTasks`、`RecentTasks.Locks` | `AppDockView` | `LauncherWidgetViews` |

| 应用启动、所选外屏与单次方向规则 | `AppLauncher` | `CoverService` | `LauncherWidgetActivity` |

桌面浏览页码由两宿主共用 `Prefs.launcherPage`，保存页码及系统启动次数；关闭、息屏和进程重建后恢复，手机重启后旧记录失效并从第一页开始。恢复等待应用目录就绪，超出当前页数时收敛到最后一页；搜索结果和展开文件夹不覆盖桌面页码。展开文件夹及返回页码仍仅保存在每个卡片实例的内存中，侧栏滚动位置由原生 ListView 保存；浏览页码不写回桌面格位，也不进入配置或布局备份。浮窗完成编辑后，由共享偏好监听刷新卡片；侧栏位置沿用左右手偏好，固定项与侧栏常用项保持独立。卡片分页箭头居中放在页码两侧，使用粗线矢量图标；保持18dp分页栏及44dp按钮宽度，不向应用列表借用高度或移动其格位，首尾不可翻页方向半透明显示。独立打开浮窗 Dock 始终从屏幕下方上滑入场，与白条位置无关。

两个宿主的 Dock 端部动作共用24dp宽度和2dp外边距，九宫格与清理按钮中心关于 Dock 中心对称；图标尺寸保持不变。横向压缩工具留白，不改变 Dock 高度、应用网格起点或格位。

启动器右上角不再显示多任务和关闭按钮，短搜索胶囊居中，排序留在同一行右侧。搜索框以行宽的62%为目标，窄屏为排序及间距保留空间；两宿主共用 `AppLauncherStyle.searchBounds`。侧栏在安全屏幕边界与应用区之间水平居中，均分两侧留白；内部四边留出4dp，设置入口独立位于侧栏下方，间隔4dp；圆形直径与32dp侧栏宽度相同，左右边缘对齐。几何由 `AppLauncherStyle` 统一管理，原生横屏／倒置布局使用相同分区；原生设置入口继续只显示编辑说明 Toast。设置图标为20dp，与侧栏图标相同；浮窗与原生分区搜索框使用32dp高度，应用区与搜索框共用16dp圆角。浮窗侧栏内容以同心内缩胶囊裁切，并在上下8dp内渐隐；原生侧栏由圆角容器裁切并使用原生列表渐隐。浮窗保留 Dock 收起和下拉收起，多任务仍可由快捷栏或控制中心的 `recents` 入口打开。

## 必须保留的宿主差异

- 原生卡片的 `launcher_background` 始终铺满三星宿主分配的区域，外轮廓裁切由宿主负责；`launcher_panel` 只承载按安全区定位的内容，不再绘制内缩的圆角背景。旋转或快捷栏避让只改变内容范围，安全区留白仍覆盖同一底色；卡片不能覆盖宿主分配区域之外的边框。浮窗的窗口与背景生命周期保持独立。
- 三星可能在90°／270°仍上报未旋转的整屏卡片宽高。仅当上报的两个轴与当前外屏的交换宽高都相符（允许整数dp取整误差）时，启动器画布采用当前显示器的实际宽高，再扣除共享安全边界；不能先按旧高度裁短。普通缩小卡片继续服从宿主尺寸，组合卡片的尺寸策略保持独立。
- 所选外屏为90°、180°、270°时，原生卡片使用与浮窗相同的主区、独立侧栏、工具行及底部 Dock 分区。`AppLauncherStyle.hubGeometry` 统一计算两宿主尺寸；`AppLauncherModel` 统一排序标签、目录状态与任务计数，页码圆点共用同一绘制函数。原生按钮翻页栏为18dp，浮窗滑动指示栏为8dp，这是网格高度的显式宿主差异。卡片优先复用 `CoverService` 已计算的浮窗安全边界，取消旧的额外20dp缩进；0°保留既有卡片表现。背景始终铺满宿主，三个旋转方向均以不透明黑色底板承托两个圆角内容区。
- 卡片使用标准 RemoteViews；应用页使用紧凑按钮翻页，侧栏通过 ListView 竖向滚动，左右滑动由三星宿主切卡。不能用本地模拟器宣称三星宿主支持内层横向手势。侧栏采用 RemoteCollectionItems 和显式 Activity PendingIntent 模板，按稳定项目 ID 更新；fill-in 点击执行前检查项目仍在当前侧栏中。
- 原生文件夹页用整条共享搜索和摘要合计高度的「‹ 全部应用 · 文件夹名」返回栏替代小箭头；90°、180°、270°复用原搜索与摘要行的合计高度，其他方向使用同一返回栏规格。返回栏任意位置均可返回，恢复打开文件夹前的页码并按当前页数校正；文件夹消失也走同一返回状态转换。Dock 九宫格在文件夹内仍禁用，不承担返回动作；配置的侧栏 app_dock 仅委托现有浮窗服务，不折叠原生卡片。
- 卡片不提供编辑或拖放，编辑入口只调用 Android 文本 Toast。不存在自制提示弹窗或确认按钮。
- RemoteViews 不承载浮窗的 EditText、拖拽和自定义任务快照手势。当前卡片直接承载应用/文件夹、侧栏及 Dock；90°、180°、270°卡片的搜索和排序入口使用显式不可变广播 PendingIntent，经过卡片身份、操作白名单、所选屏与亮屏/解锁校验后直接调用既有浮窗服务；不创建会切换焦点与系统栏的过渡 Activity，也不另存搜索或排序逻辑。锁屏时要求先解锁，服务不可用时提示开启；应用启动和任务恢复继续使用原来的 Activity 授权入口。两个启动器均不提供右上角多任务或 × 关闭按钮；侧栏设置入口独立位于侧栏下方。浮窗 Dock 保留原有展开/收起功能；原生卡片的 Dock 九宫格禁用点击，叠加 Material Symbols Rounded 的 block 禁用标记，不提供只显示 Dock 的状态，旧版 apps 切换事件也直接忽略。输入、拖放、完整任务页仍由浮窗承接，原生编辑仍只显示既有提示。侧栏中的系统工具通过已有浮窗服务执行，要求服务可用且外屏已解锁。
- 启动器 Provider 声明三星 `com.samsung.android.sdk.subscreen.widget.support_visibility_callback`，通过系统 `onAppWidgetOptionsChanged` 接收每个实例的 `visible` 状态。仅当所选外屏亮起、已解锁、当前有焦点的应用窗口标题为三星 `SubLauncherWindow`、至少一个本启动器卡片可见且浮窗未打开时，快捷栏的 `app_hub` / `app_dock` 图标在约200ms内向所在屏幕边缘滑出并淡出；离开后原位滑回，其他按钮不重排。窗口条件每次从窗口元数据重算，不依赖可能在旋转或重建后缺失的事件包名缓存。隐藏立即停用点击和无障碍入口、取消该按钮的旧按压，反向动画从当前进度继续，卸载取消动画。卡片的搜索、排序、多任务及其他入口不受这个快捷栏互斥影响；编辑仍保留原生提示，可切换到其他卡片或应用后从快捷栏进入浮窗编辑。
- 可见性只保存在内存中，按实例移除，息屏、无卡片及目标显示器变化时释放；亮屏首个实时回调先恢复显示器会话再记录。冷启动不信任持久化的旧 `visible` 值，宿主未发送、前台未知时保留快捷栏入口；不以宿主包名单独判断具体卡片，不接收未鉴权的自定义广播，不读取页面节点树、不轮询截图或任务。该能力取决于三星固件，不属于标准 Android 可见性 API；任务仍由用户点击刷新入口（90°、180°、270°为任务计数行）或浮窗结果同步，未知或失败状态明确展示且禁用旧任务操作。
- 从快捷栏整体隐藏状态首次进入三星卡片宿主时，若已绑定启动器卡片，两个重复入口在窗口挂载前先隐藏，其余按钮照常显示。卡片可见回调确认后保持隐藏，不播放首次退场；若未确认，单次等待至多600ms后恢复入口，避免不支持回调的固件永久隐藏。离开宿主、打开浮窗或卸载取消等待；重建不得让初始化中的入口提前闪现。快捷栏已显示时的正常页面切换继续使用滑出/滑回动画。
- 恢复任务必须再核对显示器、用户、任务身份与请求会话；关闭入口后迟到的结果不能影响新窗口。清理只针对点击时可见最近分组的后台任务，并重新排除固定/锁定项；重新过滤后为空只提示，不使有效列表失效。

## 后续修改的双宿主检查

公共布局参数只在 `AppLauncherStyle` 修改，两个宿主不得分别保存一组同义尺寸。`gridCell` 统一应用和文件夹占位的像素坐标；`folderGeometry` 统一方形背景、预览和标题位置，`folderIconBounds` 统一3×3预览图标。文件夹保留2×2逻辑占位，实际背景取占位宽高中较小的一边并居中，不能随非正方形网格拉长。应用图标保持等宽高。侧栏的宽度、条目高度、内边距和图文间距，以及 Dock 行高、图标、分隔线和左右留白，均引用同一组参数。打开文件夹后的成员列数、行高基准和图标大小也从该类读取。宿主各自只保留窗口、事件和 RemoteViews/View 的布局适配。

原生打开的文件夹使用 `folderMemberSurface` 计算固定3×3容量的正方形圆角底板，加共享文件夹内边距；尺寸不读取成员数量，仅在可用空间不足时整体缩小。成员沿用同一格子尺寸并居中排列，底板沿用该文件夹颜色和圆角资源。底板不接收点击或焦点，底板内外空白均由成员区处理返回。

应用列表固定横5竖3、每页15格，两宿主共用同一常量；可用高度变大、变小或调整图标规格时均不自动改变行列数，保留页内应用和文件夹格位。文件夹打开后最多3列；原生卡片成员按实际行数以共享52dp尺寸紧凑居中，空间不足时缩小，空白区域和原分页留白点击返回原页，应用成员保持启动点击；返回栏文字居中。普通应用页不注册空白返回事件。原生 Dock 禁止标记为九宫格尺寸的50%、不透明度70%，不改变槽位或点击禁用状态。紧凑卡片顶栏24dp、页码栏18dp、Dock容器36dp。侧栏条目共用20dp图标、6.4sp标签与32dp基准高度，超出容器竖向滚动，不截断已配置项目。两种启动器整体使用固定字号，不提供随系统大字号缩放或重排的模式。浮窗通过 `AppLauncherStyle.fixedFontContext` 仅将自己的 `fontScale` 固定为1；RemoteViews 字号按dp设置，防止三星宿主按系统字号二次缩放。显示密度、语言和系统字号配置保持原值，其他界面继续使用各自配置。

更新公共启动器行为时，运行 `LauncherWidgetChecks`（`launcher-widget`）及对应浮窗场景。涉及格位或 Dock 时检查 `app-folders`、`workspace-dock-menu`；涉及任务时检查 `recent-tasks`；涉及目录和图标时检查 `hub-performance`。卡片专项覆盖真实 AppWidgetHost 和 PendingIntent、编辑 Toast、两实例导航隔离、配置同步、Dock 容量与清理保护、取消后的迟到回调、错误外屏拒绝。改变可用宽高，必须验证两宿主仍保持5列3行及相同格位；切换系统字号只用于验证启动器文字和布局不变，不作为另一套适配模式。

这些检查保护共享行为，不能自动证明新 UI 同时支持两个宿主；新增 UI 必须实现对应适配，并在发行说明中明确剩余限制。三星收录、锁屏、实际目标屏、侧栏系统动作及 Shizuku 恢复/清理仍需物理真机验证。

浮窗侧栏由 `LauncherSidebarView` 复用共享液态张力渲染器，从开启安排一次固定等待：入场及余振按900ms估计，再等100ms，之后用659ms将侧栏底部的完整设置图标和圆面一起向下拉出，液颈随实际间距变细并断开，最终位置仍为原有独立按钮；不监听或协调入场完成。格位与触摸区域不随动效移动。重复开启通知不重置等待；重新拖动、收起、尺寸变化与卸载均取消等待或动画，取消后回到开启路径才重新等待。文件夹绑定共享玻璃材质，刷新名称、成员或颜色不能覆盖材质；拖动复用已挂载的原文件夹，跟手和落位同步其真实变换，取消、落位与卸载释放临时表面。颜色作为玻璃的轻微染色，降级时恢复最新颜色。Dock由 `AppDockView` 提供组级玻璃：入场时工具使用暂时独立圆面，吸合后只保留整体液态玻璃，清理扫把和九宫格保留透明按钮反馈。RemoteViews保留相同静止几何和文件夹颜色，不支持该自定义着色器及分裂动画，也不取样三星宿主背景。

浮窗启动器使用 `LauncherForce` 的八区域节点和八条连接：背板、应用容器、网格、搜索／排序／摘要整体、侧栏、设置、Dock、文件夹。`AppHubView` 用唯一受力帧回调驱动，图标继承区域的简单位移和速度轴拉伸，文字只平移；固定格位、字号及触摸区不变。侧栏先沿原 ScrollView 滚动，边界施加非线性橡皮筋反馈；按住稳定或释放回零后停帧，隐藏、卸载、多指及尺寸变化取消旧输入。`PanelGlassSession` 复用既有纹理产生小幅背景反作用，不新增截图或图标弹簧。开启、分页、拖起、文件夹及 Dock 切换共用此模型，任务页继续独占自己的 `TaskForce`。RemoteViews沿用共享静止布局和内容，不接入自定义物理帧或改变三星宿主横滑。实现与性能边界见 `launcher-force-design.md`。

侧栏设置图标起初完整显示在主体底部，与侧栏一体；圆面与图标沿同一绘制轨迹向下移动，形成液颈并在末段断开，停在原有独立位置。侧栏列表的底部渐隐随图标让出空间，分離后恢复。该动作沿用固定入场估计900ms，再停留100ms，用659ms执行，即原560ms的0.85倍速；隐藏或卸载取消等待和动画。浮窗下滑收起时，`AppHubView` 向 `GlassSurface` 和 `LauncherSidebarView` 提供到固定 Dock 上缘的实际可见高度；材质按该高度重画完整圆角、折射及描边，正文沿同一轮廓裁切，不再用原高度的玻璃被直线截断。设置圆面和图标在剩余高度内同步缩小，完全滑出后不绘制；回弹恢复原尺寸。视图测量、触摸区和应用先退出、Dock后退出的两段流程保持不变。这些绘制行为仅属于浮窗宿主。

打开文件夹的成员居中坐标在共享层按最近像素取整，避免奇数可用高度经RemoteViews换算后累计向上偏移；原生布局仍使用dp适配宿主密度，预览位图保留目标显示器像素。

浮窗及原生分区启动器内部表面与大背板留8dp空隙，由 `AppLauncherStyle.SURFACE_INSET` 和 `hubGeometry` 管理；两宿主仍固定5列3行，原生0°的既有单背景布局保持宿主差异。浮窗文件夹面板最大168dp、管理菜单最大208dp和34dp行高，删除关闭×，右侧保留编辑；成员沿共享52dp规格紧凑排列，点击宿主内的外部区域关闭，弹簧复用控制中心二级菜单并服从原安全边界。RemoteViews 文件夹仍使用原生返回栏，不创建这个浮窗二级菜单。

浮窗分页只传入实际位移差，按住边界不重复加冲量；按住侧栏的整个关联平衡在停帧时保留。文件夹玻璃取样包含 Canvas 翻页、区域平移及瞬态形变，沿用已有纹理和缓存。Dock 入场先显示紧凑应用胶囊及两侧独立工具圆面；固定入场估算900ms后再等300ms，随后用一个560ms时钟扩宽胶囊、将两端工具向中间吸合。图标全程保持原大小、padding及最终触摸槽位，应用核心不横移；同一共享张力组绘制三表面和两处连接，最终收敛为一个胶囊。无最近任务不增加右端，提前点击立即结束装饰并执行。原生 Dock 不接入该自定义吸合动画。侧栏整体的玻璃及内容平移在 `dispatchDraw()` 执行，以兼容 STACK 硬件绘制路径；顶部与文件夹绘制容器显式启用其绘制变换。
