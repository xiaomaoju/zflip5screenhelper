# 多任务的受力与连续关闭

原生实现位于 `RecentTasksView`、`TaskForce` 和 `TaskPreviewView`。交互基准为独立原型 `dist/task-force-jelly.html`：右侧为新任务，向右拖动浏览更早任务；最新、最早和中间任意任务均可停在页面中央。卡片按三张并排确定宽度，高度由宽度确定并保留上下留白；名称与状态在预览外，首尾留白用于单张居中。

`TaskForce` 只计算像素位置和速度，固定四个卡片节点、一个清理节点及一个背景节点。中心卡片和列表共用弹簧，惯性载荷经邻接弹簧传向邻卡和 X，背景产生反作用；阻尼耗散后回到原形。位置、形变与邻卡补位由 `RecentTasksView.Carousel` 的同一个帧回调更新；静止或仅等待系统结果时不继续逐帧工作。新触摸接续当前位置，取消、多指及尺寸变化取消旧动作和速度，安全结束后重新居中。

卡片按当前视口及即将补位的范围挂载，计入两侧既有裁切留白，合计至多四张，回收槽与快照按任务身份复用。完全淡出的退场卡片只保留数值状态，立即腾出槽给后面的任务，系统慢返回也不会耗尽卡片池。预览形变只作用于 `TaskPreviewView`，名称、状态和锁定标记保持原比例；清理控件与背景节点参与受力。`PanelGlassSession` 复用本次打开的背景纹理，来源失效后释放旧背景，新的窗口事件只在手势、关闭和补位稳定后更新同会话纹理，不重建手势容器。

上滑关闭的距离须严格超过预览高度的30%；短距离手势须越过系统触摸容差，并在松手时形成明确、最近100ms内的向上惯性。停顿、取消、多指、锁定、身份变化及断连不能触发关闭。下滑锁定沿用既有阈值。

每个关闭动作立即启动自己的退场及邻卡补位，其他卡片可继续横滑、关闭和锁定。请求按完整任务身份保存在有界队列中，经现有 `closeTask` / `recent_dismiss` 通道一次提交一个；没有包级强行停止。系统确认成功后，待卡片退离可视区域才提交列表移除；失败从当前位置回弹并回收补位。多个同帧移除共用一次位置记录，已存在的卡片不重新换绑、不重建页面。正在退场的快照保留到实际移除后释放；复用已加载的预览时直接呈现，只有新读取的画面渐入，避免反复从图标闪回预览。

后台结果仍由 `CoverService` / `AppRecentTasks` 校验当前宿主、目标显示器、用户和任务身份；锁定保护、Dock默认清理保护及失败提示保持原有边界。首次打开及普通刷新没有任务时保留页面，正中显示“当前没有后台任务”，隐藏无目标的清理槽；只有明确关闭最后一项成功或×清理成功才自动退出。卸载取消未提交队列、帧回调、速度追踪、预览及背景联动；已提交系统操作不伪装为可撤销。

系统已确认的关闭不可被后续请求失败回滚；失败只回弹未确认的操作，并保留此前已接收的列表。退场提交同时从可见列表和待应用列表移除该身份，避免补位恢复旧任务。任务页显示期间仅同步任务正文，不为关闭状态重建隐藏的启动器 Dock 或按最近任务重新排列隐藏应用网格；返回启动器时补齐数据。

`AppRecentTasks` 通过 `ShizukuBridge.runTask` 提交有界的单个任务请求，沿用同一串行执行器等待已提交的系统操作或预览结束。新预览让位于任务请求，首次列表读取不因普通通道繁忙而跳过并等待三秒刷新。排队期间离开页面、切换外屏或连接身份改变后，在执行前取消旧请求；不增加后台轮询或并行系统任务操作。

`CoverService.openingTaskHub` 只标记当前正在恢复任务的宿主。恢复期间同一显示器、尺寸、方向和密度下的边衬变化延后重建，结果返回后按现有显示事件合并机制重新核对；成功先令页面退出，再处理边衬。真实几何变化、强制重建或显示器生命周期结束不保存正在恢复的旧任务页，迟到回调不能操作新宿主。失败仅更新仍挂载的来源界面，不调用设置路由或自动创建任务页；迟到的玻璃准备回调不能重新启动已关闭页面的入场。

任务页统一从屏幕底部向上入场、向下跟手收起，不读取快捷按钮的 `placement.edge()`；四种快捷栏位置使用同一竖向手势。`InterfaceCard` 统一移动背板与正文，空白拖动和松手回弹使用同一位置；卡片命中区域仍保留横向浏览、上滑关闭和下滑锁定。入场与回弹的速度变化作为脉冲传入 `TaskForce`，邻卡及数值受力图共享反作用，×与背景共用受力图，不新增屏幕取样。入场脉冲系数为0.45，速度载荷上限900倍步长单位，×及背景节点仍参与数值平衡。大惯性松手采用更高阻尼，吸附期间卡片节点横向偏移限制为卡片步长1.8%，普通松手为7.3%；大惯性吸附时预览形变上限2.2%、倾斜上限0.6°，普通交互仍为5.5%和1.2°；最终位置仍精确归中，触摸中不套用吸附限幅。

缩略图先加载中心卡片，再加载视口内两个邻项，可与入场受力动画并行。`ShizukuBridge` 在既有单线程执行器排队，不因其他短请求占用而永久丢弃第一次读取。后台任务先读低分辨率系统缓存，缺失时再读正常缓存；可见任务按需调用 `takeTaskSnapshot(taskId, true)` 一次，保留系统的主题/受保护窗口规则，不取整屏画面替代。只接纳匹配包名的真实系统快照，前后重新校验显示器、用户与任务身份，缩为256px缓存。临时不可用至多重试一次，受保护、错误身份或不可用接口不重试；无周期截图或截图文件留存。

本地入口：`TaskForceTest` 回放数值弹簧和取消/惯性/居中；`UiSmokeInstrumentation` 的 `task-force` 场景在可丢弃模拟器上驱动真实View和任务身份fixture，关闭请求不进入系统任务接口。相关构建与证据位于 `Cache/tests/task-force-native/`。物理三星外屏手感、系统合成和功耗需用验证APK单独验收。

连续关闭回归入口为 `task-close-failure`（前次成功后发生失败、卡片恢复及重试）和 `task-requests`（串行通道争用、任务优先、重复请求上限及排队取消），均只使用任务身份和服务 fixture。证据位于 `Cache/tests/task-close-repair/`。

恢复任务回归入口为 `task-restore`：在自建副屏和服务 fixture 上，点击一个或三个剩余任务中的卡片，在结果尚未返回时触发真实 `reconcile`，确认来源页面不会重建，成功后退出且后续显示事件不复活。证据位于 `Cache/tests/task-restore-repair/`；不实际恢复或移除系统任务。
